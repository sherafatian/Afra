# راه‌اندازی و عملیات افرا

این کد در حال تکمیل است و **نسخه آماده بهره‌برداری نیست**. ابتدا `docs/implementation-status.fa.md` را بخوانید. سرور توسعه را در شبکه سازمان منتشر نکنید.

## اجرای معمولی

پیش‌نیاز: PHP 8.4 با PDO PostgreSQL، intl، mbstring، openssl، sodium، fileinfo، tokenizer، XML/DOM و zip؛ Composer 2؛ PostgreSQL 16 یا جدیدتر؛ Redis 7؛ Node حداقل 22.12 و npm.

۱. در BackEnd فرمان `composer install` را اجرا کنید. برای آزمون، وابستگی‌های توسعه هم لازم‌اند.

۲. `.env.example` را به `.env` کپی کنید. رمز تصادفی دیتابیس و اطلاعات اتصال را تنظیم کنید. دیتابیس اصلی `afra` و دیتابیس **کاملاً جدا و دورریختنی** `afra_test` بسازید؛ آزمون هرگز به داده واقعی وصل نشود.

۳. `php artisan key:generate` و سپس `php artisan afra:keys` را اجرا کنید. فایل محیط و کلید خصوصی نباید وارد Git شوند. فرمان کلید، فایل موجود را بازنویسی نمی‌کند.

۴. `php artisan migrate --seed` را اجرا کنید. مدیر با رمز ثابت وجود ندارد. فرمان `php artisan afra:admin admin@example.org Administrator` رمز اولیه را مخفیانه می‌پرسد. رمز قوی انتخاب کنید.

۵. PostgreSQL و Redis را راه‌اندازی کنید. برای توسعه محلی، `php artisan serve --host=127.0.0.1 --port=8000` را اجرا کنید.

۶. در FrontEnd، `npm ci` و `npm run dev` را اجرا کنید و http://localhost:5173 را باز کنید. درخواست API با پراکسی Vite به پورت۸۰۰۰ می‌رود. در تولید پراکسی سازمانی و مبدا مجاز دقیق تنظیم شود.

۷. مدیر در ورود اول گذرواژه را تغییر می‌دهد و دوباره وارد می‌شود. پروژه بسازید. تا تکمیل صفحه مدیریت حساب، کاربر دوم را از API مدیریت ایجاد و به‌عنوان بازبین مستقل به پروژه اضافه کنید. نویسنده نمی‌تواند تست خودش را تأیید کند.

فرمان `npm run build` خروجی FrontEnd/dist را می‌سازد. سرور استاتیک با بازگشت مسیرهای برنامه به index.html و پراکسی /api لازم است. فقط public لاراول وب‌روت باشد. سورس و رازها بیرون وب‌روت بماند. سرور CLI فعلی Docker فقط توسعه است؛ پیکربندی امن PHP-FPM تولید هنوز تکمیل نشده است.

## Docker برای توسعه

فایل `.env` ریشه را با `DB_PASSWORD` تصادفی و فایل BackEnd/.env را با همان رمز بسازید. بهتر است APP_KEY و کلیدهای RSA ابتدا روی میزبان تولید شوند. سپس `docker compose up -d --build` و فرمان‌های migrate و ایجاد مدیر با `docker compose exec backend php artisan ...` اجرا شوند. کلیدها از پوشه BackEnd/storage/keys مانت می‌شوند و کاربر کانتینر باید مجوز دسترسی داشته باشد (UID82 در Alpine).

APP_KEY باید در فایل محیط روی میزبان ماندگار شود؛ ساخت کلید داخل کانتینر موقت به‌تنهایی کافی نیست. پس از تغییر متغیر محیط، کانتینر بازسازی شود. دیتابیس و Redis به میزبان منتشر نشده‌اند؛ بک‌اند فقط localhost:8000 است. فرانت جدا اجرا می‌شود. Dockerfile راز اختیاری BuildKit به نام build_ca برای گواهی سازمانی ساخت دارد؛ گواهی فقط به بسته موقت همان مرحله افزوده و حذف می‌شود. اعتبارسنجی TLS را خاموش نکنید.

## آزمون

در فرانت `npm ci` و `npm run build`. در بک‌اند، با اطلاعات اتصال **دیتابیس آزمون جدا** فرمان `php artisan test` را اجرا کنید. phpunit.xml نام afra_test را تعیین می‌کند؛ RefreshDatabase داده آن را پاک می‌کند. کاربر دیتابیس آزمون به تولید دسترسی نداشته باشد. قالب‌بندی PHP با `vendor/bin/pint --format agent` انجام می‌شود. آزمون اجرا‌نشده را موفق گزارش نکنید.

## چند نود و پیش‌نیاز تولید

PostgreSQL/Redis و APP_KEY/کلیدهای قبلی/RSA باید مشترک و ایمن باشند. مبدا CORS، پراکسی‌های مورد اعتماد و TLS دقیق تنظیم شوند. مهاجرت یک مرحله هماهنگ انتشار است، نه فرمانی برای هر نود یا هر درخواست. صف و زمان‌بند با قفل مشترک و توقف امن لازم است. بررسی سلامت باید وابستگی‌ها را هم بسنجد؛ /up به‌تنهایی آمادگی دیتابیس نیست.

APP_DEBUG=false؛ سرور artisan serve برای تولید نیست. بسته‌بندی PHP-FPM، کارگر و زمان‌بند و آزمون امنیت کامل هنوز پیش‌نیازند. محدودیت وب‌سرور و PHP با۲۰MiB و سربار فرم هماهنگ شود. JSON احرازشده کش عمومی نشود. توکن، کوکی، رمز، کد ملی و بدنه درخواست در لاگ نیاید.

## پشتیبان و نگهداری

عملیات از PostgreSQL پشتیبان سازگار می‌گیرد و بازیابی آزمایشی انجام می‌دهد. قطعه‌های پیوست، فراداده، تاریخچه و نسخه‌ها با هم حفظ شوند. APP_KEY و کلیدهای رمزنگاری قبلی جدا و امن نگهداری شوند؛ دیتابیس بدون کلید فایل‌های رمز‌شده را بازیابی نمی‌کند. کلیدهای امضای جاری/قبلی مطابق سیاست چرخش حفظ شوند. پاک‌سازی گزارش مصرف نباید تاریخچه و پیوست را حذف کند. گزارش مصرف سرویس نیز به‌صورت پیش‌فرض دائمی بماند؛ هیچ کار پاک‌سازی بدون تصمیم صریح بعدی سازمان فعال نشود.

هنوز ظرفیت بار تضمین نشده است. عدد۱۰۰هزار مربوط به حساب ثبت‌شده است. پیش از استقرار، صفحه‌بندی همراه ACL، درخت، تجمیع گزارش و دانلود هم‌زمان۲۰MiB با بار واقعی اندازه‌گیری شود.
