# به‌روزرسانی نصب توسعه برای برنامه‌ریزی و مراحل مشترک

این تغییر به معنای پذیرش انتشار کامل نیست؛ قابلیت‌های باقی‌مانده در سند پذیرش انتشار مشخص‌اند. سرویس‌های اکسپوزی از این فاز خارج‌اند و استقرار سازمانی با مالک است. راهنماهای کاربری تغییر نکرده‌اند.

در ویندوز، بدون Docker یا Herd، از مخزن موجود:

```powershell
git pull --ff-only
cd BackEnd
composer install
php artisan optimize:clear
php artisan migrate
php artisan afra:check
cd ..\FrontEnd
npm ci
npm test
npm run build
```

مهاجرت را یک بار روی دیتابیس PostgreSQL مشترک اجرا کنید. نسخه رکورد، پیش‌نمایش تأیید، اطلاعات ثابت برنامه/انتشار/پیکربندی/داده، ترتیب مشاهده/خط مبنا و بازبینی مراحل مشترک افزوده می‌شود. نتایج و پیوست‌های قبلی حفظ می‌شوند. رکورد عمومی قدیمی مراحل مشترک برای استفاده جدید باید نسخه‌ای با نویسنده مشخص و تأیید مستقل داشته باشد. از `migrate:fresh`، بازسازی داده واقعی، تولید دوباره کلید امضای موجود یا تغییر APP_KEY استفاده نکنید؛ پیوست رمز‌شده به کلید قبلی وابسته است.

برای توسعه محلی، در دو پنجره جدا، داخل BackEnd دستور `php artisan serve --host=127.0.0.1 --port=8000` و داخل FrontEnd دستور `npm run dev -- --host 127.0.0.1` را اجرا کنید. پراکسی فعلی پورت۸۰۰۰ را هدف می‌گیرد. استقرار واقعی از خروجی ساخته‌شده فرانت و وب‌سرور/کارگر بومی مطابق الگوهای استقرار استفاده می‌کند. این قابلیت‌ها بسته زمان‌اجرای جدید Composer/npm ندارند. نودها باید سورس، مهاجرت، دیتابیس/کش مشترک و تاریخچه کلید یکسان داشته باشند.

برای بررسی عملی، داده نوع‌دار و ماتریس پیکربندی بسازید، تست را مستقل تأیید و برنامه تعریف کنید؛ پیش‌نمایش ترکیب‌ها را ببینید و با حفظ موارد الزامی تأیید کنید. در مراحل مشترک، چک‌لیست را ذخیره، درخواست بازبینی و با کاربر مجاز دیگری تأیید کنید؛ سپس نسخه تأییدشده را به پیش‌نویس تست متصل کنید. تغییر مجموعه مشترک مصرف‌کننده‌ها را خودکار ارتقا نمی‌دهد. دکمه گزارش کیفیت اجرا/انتشار، شاخص‌های دارای فیلتر دسترسی و چاپ همه ردیف‌ها را ارائه می‌کند.

Composer اکنون افزونه‌های لازم قبلی PHP، از جمله intl و PDO PostgreSQL و sodium را صریح بررسی می‌کند. آن‌ها را در php.ini خط فرمان و وب‌سرور فعال کنید؛ روی ماشین استقرار بررسی پیش‌نیازها را نادیده نگیرید.
