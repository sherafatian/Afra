# Deployment templates — no Docker required

These are reviewable infrastructure templates, not a production release or evidence of a tested organization deployment. Full product/security/load acceptance is still incomplete. Do not deploy the current application as a finished system.

Linux: configure PHP8.4-FPM, shared PostgreSQL/Redis, TLS and the Nginx template. Serve FrontEnd/dist; send only /api to BackEnd/public/index.php. Supervisor template provides supervised shared-queue workers. A single coordinated deployment step installs dependencies, migrates and caches configuration; never run migrations separately on every node/request. Use `php artisan queue:restart` after deploying workers. If scheduled jobs are added, run `php artisan schedule:run` every minute under the application identity with a shared cache for locks. No operational scheduled jobs currently exist.

Windows: native PHP8.4 NTS + IIS CGI/FastCGI, URL Rewrite and ARR. Create two sites: backend bound only to127.0.0.1:8081 with physical path BackEnd/public, and frontend bound to the real HTTPS hostname with physical path FrontEnd/dist. Review/copy each .web.config.example as web.config in its respective public directory. Configure the FastCGI application and matching handler executable path at server level. Set FastCGI request timeout above120seconds and PHP post/upload limits24M/20M. Enable ARR proxy and allow the documented rewrite server variable. Set `TRUSTED_PROXIES=127.0.0.1` for this loopback proxy topology only; use exact actual load-balancer addresses for any different topology. Restrict backend binding/firewall; never publish artisan serve. These IIS templates are XML-validated but have not been executed on Windows here.

Grant the application identity read access to source/config/private keys, and write access only to storage and bootstrap/cache. On Windows use NTFS ACLs; chmod alone is not an NTFS access-control policy. Keep source/.env/vendor/keys outside web roots. Use a dedicated identity, not an administrator account. Never put secrets in frontend VITE variables. Do not commit configured deployment files containing operational values.

Set APP_ENV=production, APP_DEBUG=false, APP_URL and FRONTEND_ORIGINS to the exact HTTPS origin, a persistent shared APP_KEY and identical signing configuration across nodes. JWT_SIGNING_KID selects the active pair. JWT_PREVIOUS_PUBLIC_KEYS is a JSON map of previous kid to absolute PUBLIC-key path; deploy both current/previous verification keys before switching the active signer and retain previous keys for the required access-token overlap. Do not overwrite the active key pair with afra:keys. Proxy trust is loaded from cached configuration and must not be wildcard. Internal frontend/API proxy preserves /api without adding a second prefix.

Run `php artisan afra:check --production`; inspect all failures before routing requests. `/api/ready` reports dependency/migration readiness only, not feature/release acceptance. Always complete and retain acceptance evidence, restoration drills and measured workload tests separately. Current readiness intentionally reports release_acceptance=incomplete even when dependencies are healthy. An actual load balancer, TLS certificates, NTFS permissions, IIS/ARR modules and worker service management require environment-specific operations validation.
